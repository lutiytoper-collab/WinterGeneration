# Установка 0.7.0

Платформа строго Paper/Purpur 1.21.11, Java 21. Один MidgardWinterWorld.jar содержит всё необходимое для оформления и native рельефа. WinterProbe.jar только для QA, в игровой plugins/ не устанавливайте.

1. Подготовьте **новый обычный NORMAL мир** на тестовом сервере. Остановите сервер перед заменой JAR. Старую копию плагина уберите, оставьте один новый файл.
2. Старая конфигурация сохраняется. fantasy-terrain-enabled по умолчанию true, даже если ключ отсутствовал. Если нужен прежний рельеф, заранее скопируйте поставляемый config.yml в plugins/MidgardWinterWorld/ и поставьте false до создания мира.
3. Запустите сервер. В логе должны быть FANTASY_PACK_DISCOVERED MidgardWinterWorld/fantasy и FANTASY_TERRAIN_ENABLED true. Отдельный внешний datapack ZIP не нужен. Для изменения профиля нужен полный restart, reload недостаточно.
4. Для позднего декора нового имени мира добавьте его в allowed-worlds; по умолчанию world/winter_test. Native registry рельефа/биомов применяется ко всем обычным Overworld worlds с этими noise settings, отдельно по allowed-worlds не ограничивается.
5. Осмотрите область и выполните ограниченную предварительную генерацию. Для Luna проверьте диапазон высот в generators.yml:QA на новом рельефе использовала max-y 280 и стандартную площадку 5×5.

Не смешивайте старые внешние storybook-datapack.zip/winter-datapack.zip/terrain ZIP со встроенным профилем. Отдельные ZIP — альтернативные данные для ручной настройки, не дополнительные шаги обычной установки. modules.schematics управляет арками/руинами/святилищами, modules.wonders — ивами/грибами/камнями.

Старые чанки/ценные блоки автоматически не заменяются. Смена профиля на существующем мире способна дать резкие стыки. Native цвета/климат могут влиять и на отображение старых биомов. Удаление JAR не удаляет готовый ландшафт; полный откат требует согласованной резервной копии.

Тёплые биомы не зимние, Nether/End не меняются. Новые объекты разрушаемые, без собственных приватов; protect-player-builds/WG ограничивают генератор, а не права игроков. Правила других плагинов настраиваются отдельно. Нагрузка 50–100 игроков не проверена. Подробности: TERRAIN.md, ANARCHY.md и reports/KNOWN_ISSUES.md.

В версии0.7.0 добавлены пологие PvP-луга с небольшими холмами, деревьями и структурами. Проверенный квадрат64×64 и правила генерации описаны в PVP_FIELDS.md; это обычная разрушаемая местность с редкими укрытиями и постройками, без отдельного региона.

Для анархии с разрешённым строительством у самого спавна установите `spawn-protection=0` в server.properties. Плагин не переписывает этот параметр и правила сторонних регионов.
