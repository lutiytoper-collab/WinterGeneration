# Производительность: настоящие измерения

Paper 1.21.11 build 132, Java 21.0.9+10, Linux amd64; cgroup CPU quota 4 ядра, memory limit 32 GiB. Каждый сервер матрицы: Xms512M/Xmx2G, view-distance=3, simulation-distance=3, без игроков, tick freeze одинаково в vanilla и winter. Три seed, по 256 последовательных запросов на ветку и повтор после restart: 1536 уникальных ROI-чанков, 3072 запроса с restart. Стартовая точка чанков 128,128, квадрат 16×16. Дополнительные spawn/halo чанки сюда не входят.

Измеряется полная задержка `getChunkAtAsync` от запроса до completion, включая очередь, фоновые стадии и подготовку соседей. Последующий запрос может попасть в уже подготовленный чанк; субмиллисекундная медиана не означает генерацию нового чанка за такое время. Тест не изолирует CPU worldgen и не является TPS-тестом SMP.

Средние winter-задержки в этих трёх парах выше vanilla примерно на 4.2%, 3.2% и 32.1%. Единичные прогоны без статистических повторов не устанавливают постоянный overhead. Heap start/end отражает точки выборки и GC, не peak/RSS; из меньшего heapEnd нельзя выводить экономию памяти. Полные значения и existed flags — reports/runtime, исходные summary JSON перечислены выше.

Серверный `/winterworld benchmark` отдельно хранит реальные времена отложенной обработки декора: максимум 4096 последних образцов для median/P95, среднее/максимум за всё время. Он **не** включает основную генерацию, отдельный ClimateBoundaryGuard и async-подготовку аирдропа. Soft tick budget не прерывает выполняемый объект. Эти цифры нельзя выдавать за полную стоимость чанка.

Интеграционные серверы Luna использовали Xmx4G, локальный Mineflayer и иной профиль нагрузки; их задержки поиска не смешиваются с матрицей. Публичный native Generator адаптирован для async-подготовки; до 16 подготовок, до 32 районов за пять минут на дроп, до 16 поверхностных позиций на район. Подготовленный неактивный район держится не более 30 секунд.

Длительный стресс 50–100 игроков, реальные боевые плагины, пиковый RSS, стабильный TPS, массовые одновременные дропы и fault-injection остаются NOT RUN. Ограниченные реальные Chunky-задачи проверяют совместимость и идемпотентность, а не доказывают производительность публичного сервера.
